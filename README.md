# tart-mcu-code

PlatformIO firmware for the TART motherboard microcontroller. An **CH32V003F4U6**
(RISC-V, 48 MHz, 16 KB flash / 2 KB RAM) that configures the **MAX2769B/C** GNSS
radio front end at boot, and then runs an LED pattern.

There is no console/UART output: the firmware's whole job is the power-up and
register-configuration sequence for the radio.

## Hardware interface

Defined in [`src/hardware.h`](src/hardware.h):

| Signal | Pin | Notes |
|---|---|---|
| `SHDN#` (`TART_SLOT_ENABLE`) | PD2 | Active low; held low for 1.5 s at boot |
| `PGM` | PD3 | High = preconfigured (OTP) state, low = serial interface |
| `SCLK` | PD4 | MAX2769 3-wire serial clock |
| `CS#` | PD5 | MAX2769 3-wire chip select |
| `SDATA` | PD6 | MAX2769 3-wire serial data |
| `RADIO_RECONFIG` | PC4 | Defined but not driven by this firmware |
| LED | PC2 | Assumed active-high (see `pulse_led()`) |

The reference frequency assumed throughout is **16.368 MHz**.

## Building

Requires [PlatformIO Core](https://platformio.org/install/cli) (`pio`). The
`ch32v` platform, `framework-wch-noneos-sdk` and the RISC-V toolchain are
installed automatically on first build.

```bash
pio run                 # build (reports flash/RAM usage)
pio run -t clean        # remove build artefacts
pio run -t upload       # flash over the default WCH-Link probe
```

A clean build of both radio modes (see below) succeeds with no warnings and uses
~59% of flash.

### Upload options

The board defaults to `wch-link`; other protocols are supported by the platform:

```bash
pio run -t upload --upload-protocol minichlink   # ESP-based minichlink
pio run -t upload --upload-protocol isp          # serial bootloader (wchisp)
pio run -t upload --upload-protocol wlink        # wlink
```

(or set `upload_protocol` in `platformio.ini`).

## Build options

### 1. Radio operating mode — `TART_RADIO_SERIAL_CONFIG`

Selected at compile time in [`src/main.c:14`](src/main.c):

```c
// #define TART_RADIO_SERIAL_CONFIG    // <- uncomment to switch mode
```

| | **Undefined (default)** — preconfigured OTP | **Defined** — serial configuration |
|---|---|---|
| How the chip is set up | Pin levels select OTP state 2 (Table 3): SCLK=0, DATA=1, CS=0 | Registers written over the 3-wire interface, `PGM` held low |
| Outputs | I channel only, 2-bit, CMOS | I **and** Q, 1-bit, CMOS (parallel pins) |
| IF filter | 4.092 MHz centre, 2.5 MHz bandwidth | ~4.08 MHz centre, 4.2 MHz bandwidth |
| PLL dividers | OTP defaults | Written explicitly (`DIV = 0x0C00080`) |
| Registers programmed | none | CONF1, TEST2, CONF2, CONF3, PLLCONF, DIV |

Either enable it in the source, or pass it as a build flag without touching the
file:

```bash
PLATFORMIO_BUILD_FLAGS="-DTART_RADIO_SERIAL_CONFIG" pio run
# or permanently, in platformio.ini:
#   build_flags = -DSYSCLK_FREQ_48MHZ_HSI=48000000 -DTART_RADIO_SERIAL_CONFIG
```

> The two modes present **different data formats to the FPGA** (I-only/2-bit vs
> I+Q/1-bit), so make sure the downstream logic matches the mode you flash.

### 2. Streaming variant

`setupRadio()` (parallel outputs) is used when serial mode is enabled. The DSP
streaming variant `setupRadioStream()` — STRMEN/STRMSTART, 2-bit ADC — is one
comment away in the same block.

Do not enable it blindly: with the current `CLK` word the serial clock may end up
no faster than the ADC clock, while the datasheet requires `SERCLK >= 2 x ADC
clock` for the `STRMBITS = 10` (I MSB + Q MSB) serialisation. Measure both
clocks on the bench first (see the `getCLK()` comments in
[`doc/max2769_conf.py`](doc/max2769_conf.py)).

### 3. System clock

48 MHz (HSI + PLL) is pinned by `platformio.ini`:

```ini
build_flags = -DSYSCLK_FREQ_48MHZ_HSI=48000000
```

It has to be a command-line macro: `system_ch32v00x.c` is a separate translation
unit and never sees a `#define` in a source file. Delays are derived at runtime
via `SystemCoreClockUpdate()`, so they stay correct either way.

## Register values

The words in [`src/max2769.c`](src/max2769.c) are generated by
[`doc/max2769_conf.py`](doc/max2769_conf.py):

```bash
python3 doc/max2769_conf.py            # parallel-output configuration
python3 doc/max2769_conf.py --stream   # DSP streaming configuration
```

The printed lines are ready to paste into `setupRadio()` / `setupRadioStream()`
(address + full 28-bit data word). Keep the two in sync — the generator prints
exactly the sequence the firmware sends.

Bits worth knowing about:

- **IF centre frequency** — `FCEN` (CONF1 D10:D5) *plus* `FCENMSB` in **TEST2
  bit 0**; a 7-bit word. The firmware writes `TEST2 = 0x28C0403` so that
  `FCEN = 001011` with `FBW = 10` lands at ~4.08 MHz, matching the 4.092 MHz IF
  produced by the PLL (16.368 MHz / 16 x 1536 = 1571.328 MHz, and
  1575.42 - 1571.328 = 4.092 MHz).
- **`DIV`** is always written explicitly — Note 1 of the datasheet says power-on
  defaults are not production tested or guaranteed.

## Known caveats

- The MAX2769B and MAX2769C datasheets disagree with each other on the plain
  `FCEN` code table (and contradict themselves internally in a couple of places:
  `FCLKIN` polarity, CONF2 reserved D2). Values here follow the **MAX2769C**
  formula, which reproduces the datasheet's own worked examples exactly — but
  confirm the actual IF and the ADC/serial clocks on hardware.
- The serial framing in `max2769set()` is data-first (28 data bits, then the
  4-bit address), per the datasheet's *"A 32-bit word, with the MSB (D27) being
  sent first"*. This looks backwards; it is correct.
- Bit-banged SPI runs at ~16 kHz (delays are given in µs where the datasheet
  specifies ns) — conservative and safe, ~3 ms per register.
- `pulse_led(period, high_percent)` assumes an active-high LED; swap the two
  delays if the LED sinks current instead.
